# Контракт локальных Tool

## 1. Назначение и общие правила

Tool — локальная прикладная операция, зарегистрированная в `ToolRegistry` и вызываемая только через `Dispatcher`/`JobExecutor`. Tool не является отдельным процессом или удалённым сервисом. Tool не обращается к UI и не управляет состоянием Job напрямую.

### Общий интерфейс (Python Protocol)

```python
from dataclasses import dataclass
from typing import Protocol, Generic, TypeVar

I = TypeVar("I")
O = TypeVar("O")

@dataclass(frozen=True)
class ToolError:
    code: str
    message: str
    field: str | None = None
    retryable: bool = False
    details: dict[str, object] | None = None

@dataclass(frozen=True)
class ToolResult(Generic[O]):
    value: O | None = None
    error: ToolError | None = None

class Tool(Protocol, Generic[I, O]):
    name: str
    version: str
    input_schema: dict[str, object]

    def execute(self, input: I, context: "ToolContext") -> ToolResult[O]: ...
```

`ToolContext` предоставляет `job_id`, `request_id`, `deadline`, `cancellation_token`, `logger` и доступ к разрешённым портам/адаптерам. Контекст не содержит ссылок на виджеты UI.

### Валидация и ошибки

- **Вызывающий слой (Dispatcher/Registry)** проверяет JSON/schema-форму, обязательные поля, типы, размер строк, допустимое имя Tool и права на операцию до вызова.
- **Сам Tool** повторно проверяет доменные инварианты, которые важны для безопасности и корректности: контрольную сумму ISBN, канонический ISBN, допустимые источники, deadline/cancellation и согласованность издания.
- Ошибка не маскируется пустым результатом. Tool возвращает ровно один из вариантов: `value` или `error`; одновременно оба поля заполненными быть не могут.
- Повторять можно только ошибки с `retryable=true`, в пределах общего deadline и с ограниченным числом попыток. Ошибки валидации, несовпадение издания и запрет доступа не повторяются.
- Исключения внешней библиотеки преобразуются в типизированные `ToolError`; traceback остаётся в локальном логе без секретов. Секреты и токены не включаются в `details`.

## 2. Tool: ValidateIsbnTool

**Вход:** `{"isbn": "978-..."}`.  
**Выход:** `{"isbn13": "978...", "was_converted_from_isbn10": false}`.

**Поведение:** удаляет допустимые разделители, проверяет формат и контрольную цифру ISBN-10/ISBN-13, преобразует валидный ISBN-10 в ISBN-13. Не обращается к сети и не ищет цены.

**Ошибки:**

| Код | Когда | Поле | Повтор |
|---|---|---|---|
| `ISBN_REQUIRED` | ISBN пуст | `isbn` | Нет |
| `ISBN_FORMAT_INVALID` | Недопустимые символы/длина/префикс | `isbn` | Нет |
| `ISBN_CHECKSUM_INVALID` | Контрольная цифра не совпала | `isbn` | Нет |

**Проверки:** Tool сам проверяет контрольную сумму; вызывающий до вызова проверяет тип и максимальную длину поля.

## 3. Tool: ResolveBookTool

**Вход:** `{"query": {"isbn13": "..."}}` или `{"query": {"title": "...", "author": "..."}}`.  
**Выход:** список `BookCandidate`: `edition_id`, `title`, `authors`, `isbn13`, `publisher`, `publication_year`, `language`, `match_reason`.

**Поведение:** вызывает библиографический адаптер, нормализует кандидатов и не выбирает неоднозначное издание автоматически. Для текстового запроса возвращает кандидатов; UI просит пользователя подтвердить издание. Для точного ISBN приоритетно возвращается совпадение ISBN-13.

**Ошибки:**

| Код | Когда | Поле | Повтор |
|---|---|---|---|
| `BOOK_QUERY_INVALID` | Нет ISBN и нет title либо оба несовместимых варианта | `query` | Нет |
| `BOOK_NOT_FOUND` | Провайдер ответил успешно, кандидатов нет | `query` | Нет |
| `BOOK_PROVIDER_TIMEOUT` | Провайдер не ответил до timeout | `query` | Да |
| `BOOK_PROVIDER_UNAVAILABLE` | Провайдер временно недоступен/вернул 5xx | `query` | Да |
| `BOOK_PROVIDER_RESPONSE_INVALID` | Ответ не соответствует ожидаемой схеме | `null` | Нет; требуется разбор интеграции |

**Проверки:** вызывающий проверяет схему запроса; Tool проверяет доменную валидность ISBN, нормализует и валидирует ответ адаптера.

## 4. Tool: SearchStoreOffersTool

**Вход:** `{"edition": {"edition_id": "...", "isbn13": "..."}, "source_ids": ["store_a", "store_b"]}`.  
**Выход:** `{"offers": [Offer...], "source_results": [{"source_id": "...", "status": "success|error|timeout", "error_code": null}]}`.

`Offer` содержит `source_id`, `title`, `isbn13`, `price_minor`, `currency` (для MVP `RUB`), `delivery_minor` (nullable), `availability`, `product_url`, `fetched_at`.

**Поведение:** запускает разрешённые StoreAdapter независимо, применяет индивидуальный timeout 8 секунд и общий deadline Job 15 секунд, возвращает успешные предложения вместе с результатами по каждому источнику. Ошибка одного магазина не отменяет остальные. Каждый элемент ответа валидируется отдельно: валидные Offers сохраняются, невалидные отбрасываются и учитываются как `STORE_RESPONSE_INVALID` с индексом элемента в диагностике. Сопоставимость ISBN проверяется до передачи Offer дальше по конвейеру. Если после обработки есть хотя бы один Offer и есть ошибки источников/элементов, Job завершается `PARTIAL`; если ни один источник не дал пригодного ответа до deadline — `TIMED_OUT`; если все ответы протокольно некорректны и Offer нет — `FAILED`; если все источники корректно ответили без Offer — `NO_RESULTS`.

**Ошибки Tool:**

| Код | Когда | Поле | Повтор |
|---|---|---|---|
| `EDITION_REQUIRED` | Не передано подтверждённое издание | `edition` | Нет |
| `SOURCE_NOT_ALLOWED` | Источник отсутствует в Registry/allowlist релиза | `source_ids` | Нет |
| `STORE_TIMEOUT` | Источник не ответил в отведённое время | `source_ids` | Да, ограниченно |
| `STORE_UNAVAILABLE` | Временная ошибка источника | `source_ids` | Да, ограниченно |
| `STORE_RESPONSE_INVALID` | Неожиданная схема/тип цены/валюта | `source_ids` | Нет |
| `OFFER_URL_REJECTED` | URL не HTTPS или домен не разрешён | `product_url` | Нет |
| `JOB_CANCELLED` | Получен cancellation token | `null` | Нет |

**Проверки:** вызывающий проверяет структуру и наличие `edition`; Tool проверяет доменную целостность ISBN, allowlist источников, deadline и cancellation. Адаптер отвечает за проверку схемы внешнего ответа и преобразование цены в целые минимальные единицы валюты.

## 5. Tool: NormalizeOffersTool

**Вход:** список сырых нормализованных Offer и идентификатор выбранного издания.  
**Выход:** дедуплицированный список Offer, отсортированный по цене товара; итог «товар + доставка» вычисляется только если доставка известна.

**Ошибки:** `OFFER_EDITION_MISMATCH`, `OFFER_PRICE_INVALID`, `OFFER_CURRENCY_UNSUPPORTED`, `OFFER_NORMALIZATION_FAILED`. Ошибки несопоставимого Offer приводят к отбрасыванию конкретного предложения с диагностикой; фатальная ошибка модели/обработки переводит Job в `FAILED`.

**Проверки:** Dispatcher проверяет форму входного сообщения; Tool проверяет валюту, неотрицательность цены, ISBN и URL, а также не трактует неизвестную доставку как ноль.

## 6. Ограничения внешних ответов StoreAdapter

Каждый адаптер обязан ограничивать размер HTTP-ответа (настраиваемый лимит, значение по умолчанию 2 MiB на один ответ), применять connect/read timeout, проверять content type и структуру ответа до создания Offer. Timeout одного адаптера по умолчанию 8 секунд; общий deadline Job — 15 секунд. Повторяются только временные ошибки и только пока не истёк общий deadline. Цена должна быть конечным неотрицательным целым числом в минимальных единицах валюты; для MVP валюта только `RUB`. Невалидная запись не передаётся в NormalizeOffersTool. Превышение размера, неверный тип/валюта или схема ответа возвращают `STORE_RESPONSE_INVALID` для соответствующего источника; остальные источники продолжают работу.
