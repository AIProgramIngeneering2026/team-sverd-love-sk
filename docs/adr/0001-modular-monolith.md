# ADR-0001: Модульный монолит в одном процессе

- **Дата:** 2026-11-14
- **Статус:** Accepted

## Контекст и ограничения

BookScout — небольшое desktop-приложение на Python/PySide6. Основные функции — поиск библиографических записей, вызов нескольких внешних источников цен, нормализация и локальное хранение. Команда и бюджет MVP ограничены; отдельное развёртывание сервисов, брокер сообщений и эксплуатация серверной инфраструктуры не входят в цель. При этом интеграции должны быть изолированы, чтобы изменения API магазинов не затрагивали доменную логику.

## Решение

Реализовать один процесс и один репозиторий как модульный монолит с границами UI/CLI → Dispatcher → Registry/Tools → порты адаптеров и Repositories. Конкретные адаптеры реализуют интерфейсы, определённые приложением. Внешние API остаются внешними зависимостями, а не собственными микросервисами BookScout.

## Рассмотренные альтернативы

1. **Набор микросервисов.** Отклонено: добавляет сетевое взаимодействие, деплой, мониторинг и распределённую согласованность без пользы для локального MVP.
2. **Монолит без модульных границ.** Отклонено: смешивает UI, правила сравнения и парсинг конкретных магазинов; усложняет тестирование и замену источников.
3. **Плагины в отдельных процессах.** Отклонено: избыточная изоляция для двух первых интеграций; потребует IPC и протокола версионирования.

## Цена решения

- Все Tools используют общие ресурсы процесса; сбой нативной библиотеки может повлиять на приложение.
- Нельзя независимо масштабировать интеграции.
- Требуется дисциплина зависимостей и запрет на импорт UI из доменного/application слоя.

## Условия пересмотра

Пересмотреть ADR, если появится серверная версия с несколькими пользователями, необходимость независимо развёртывать/масштабировать источники, изоляция ненадёжного стороннего кода или отдельная команда сопровождения интеграций.
