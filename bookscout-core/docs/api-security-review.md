# Наш API против нарушений Н40–Н49

Проверка относится к MVP BookScout: локальный single-user сервис, который создаёт Job поиска книги по ISBN и возвращает найденные предложения. API по умолчанию слушает только `127.0.0.1`; все операции требуют Bearer token из `BOOKSCOUT_API_TOKEN`. В API нет управления пользователями, заказов, исполнителей, оплаты или отдельного каталожного CRUD.

| Нарушение | Применимость и защита | Проверка |
|---|---|---|
| **Н40 — Чужой Job** | Многопользовательских аккаунтов и разных владельцев Job в MVP нет: все запросы принадлежат одному локальному пользователю. Доступ к API требует секретный Bearer token; без него чтение Job возвращает `401`. Для многопользовательского/удалённого режима потребуется owner_id и проверка владельца в каждом запросе. | `test_authentication_is_required`, `test_api_binds_access_to_single_local_principal` |
| **Н41 — Сам себе статус** | В API нет `PATCH`/`PUT` для произвольной установки статуса или цены. Есть только отдельная команда `POST /jobs/{job_id}/cancel`; она вызывает `Job.cancel()`, а не записывает статус напрямую. Недопустимая отмена терминальной Job возвращает `409 job_invalid_transition`. | `test_api_does_not_expose_job_state_mutation`, `test_api_invalid_transition_has_conflict_status`; unit-тесты З3–З6 в `test_core.py` |
| **Н42 — Пароль исполнителя** | Неприменимо: в BookScout нет исполнителей, их учётных записей или операций смены пароля. | Неприменимо по модели предметной области. |
| **Н43 — Весь каталог разом** | Отдельного API каталога нет. Поиск ограничен одной Job и одним изданием; дополнительно `SearchStoreOffersTool` возвращает не более 1000 предложений на Job, отмечая усечение в `source_results[].truncated`. | `test_offer_search_never_returns_more_than_1000_records` |
| **Н44 — Служебный возврат** | Служебных операций нет. Dispatcher принимает только зарегистрированный workflow `books.search`; неизвестная операция отклоняется как `unknown_operation` с HTTP `422`. | `test_api_has_no_support_only_or_unregistered_operation`, `test_unknown_operation_is_explicit_error` |
| **Н45 — Минус товар** | Понятия количества товара в API нет. Контракт `books.search` принимает только `isbn`; неизвестный параметр `quantity` не игнорируется, а отклоняется schema-валидацией до создания Job. | `test_extra_parameter_quantity_is_rejected_not_ignored` |
| **Н46 — Оплата без денег** | Неприменимо: BookScout не принимает оплату и не хранит статус оплаты. Job поиска книги не является заказом. | Неприменимо по модели предметной области. |
| **Н47 — Двойной клик** | Создание Job требует `Idempotency-Key`. Повтор с тем же ключом и тем же каноническим телом возвращает существующую Job; уникальность ключа обеспечивается SQLite, а не памятью процесса. | `test_idempotency_same_key_same_body_returns_same_job` |
| **Н48 — Двойное списание** | Списания денег и платёжных side effects в системе нет. Повтор создания поиска с тем же ключом не создаёт вторую Job, то есть не дублирует действие на уровне BookScout. | `test_idempotency_same_key_same_body_returns_same_job` |
| **Н49 — Старый ключ, новое тело** | Для каждого ключа хранится SHA-256 канонического тела запроса. Повтор с тем же ключом, но другим телом получает `409 idempotency_key_reused`; вторая Job не создаётся. | `test_idempotency_same_key_different_body_is_conflict_even_if_operation_unknown` |

## Ограничение модели доступа

Текущая авторизация — один локальный principal, общий секрет и loopback bind по умолчанию. Это осознанное ограничение desktop-MVP, а не полноценная multi-tenant авторизация. Если API будет доступен по сети нескольким пользователям, Н40 нужно закрыть отдельной моделью пользователей/владельцев и проверкой `owner_id` на уровне репозитория или сервисного слоя.
